# Network

These notes describe security and maintenance details behind the package behavior documented in the package READMEs. See [architecture.md](architecture.md) for boundaries and invariants.

## Web fetch challenges

In-process Anubis proof-of-work interstitials are solved inside the same boundary: challenge and pass requests reuse the pinned transport, a server-provided WebAssembly module runs in a worker thread terminated on cancellation with allowlisted imports and a byte/time budget, and cookies live in memory for one acquisition. Methods or extensions outside the in-process set report the standard block.

AWS WAF solving runs in-process by default: the resolver fetches the challenged page and challenge metadata through the same validated, pinned, bounded transport and per-acquisition cookie jar, builds browser fingerprint signals, solves the advertised proof of work in a bounded worker terminated on cancellation, and posts the solution. The returned token is validated, stored in the per-acquisition cookie jar, and used for one retry through the same redirect and pinned transport with the browser identity that earned it. The resolver does not execute the downloaded challenge script, launch a browser, or use an alternate TLS transport. A failing or invalid solve degrades to the standard block or documentation-index fallback.

## OpenCode Free provider

`pi-opencode-free` delegates streaming to Pi's native OpenAI completions implementation. Its provider-scoped adapter applies the free-tier request contract after any caller payload hook, including tool-free compaction and branch-summary requests. It preserves caller instrumentation, cancellation, and native usage accounting. Only a confirmed free-usage 429 receives a human-readable quota notice; reset times come from `Retry-After`, never an assumed daily schedule. Quota errors format the server-reported reset time in the Pi process's locale and timezone. Quota evidence remains request-local; there is no status command, cached countdown, or inference probe.

The OpenCode Free provider registers the OpenCode inference endpoint with the public token and reads no endpoint, API-key, or CLI-version environment overrides. It resolves the request version lazily at runtime from the official installer's fixed `https://opencode.ai/update/api/latest/cli/npm` metadata endpoint, falling back to `@opencode/cli`'s npm `latest` metadata. Both sources use credential-free HTTPS, no redirects, a five-second per-source deadline, a 64 KiB response bound, and identity and stable-version validation. No remote URL is followed and no installer or binary is downloaded or executed. A shared lookup serves independently cancelable callers and aborts when its last waiter cancels. Only successful versions are cached in memory for 24 hours; failures are retryable, and no synthetic or bundled version is substituted. Registration and offline model refresh make no version request. A published version is traceable upstream metadata, not a guarantee of third-party-client support or an exemption from service limits.

OpenCode Free discovery follows native Pi's four-hour refresh interval, requiring both `checkedAt` and `lastModified` before skipping network access. The persisted entry keeps the visible live selection in `models` and the complete validated free-metadata projection in the provider-owned `catalog` field, with Pi's standard `etag` and `lastModified` fields. Conditional pi.dev requests send `If-None-Match` only when a nonempty metadata body backs the validator; a `304` reuses that body while still applying the refreshed live selection. This retains metadata for models that were not previously live. A `200` replaces metadata and validators; `404`/`501` record an empty overlay with `lastModified: 0` and clear the validator. Other HTTP failures preserve the cached body and validators, advance `checkedAt`, and surface a bounded refresh error, matching native Pi; without prior `lastModified`, those failures remain immediately retryable. Transport, parsing, CLI-version resolution, timeout, and cancellation failures do not advance freshness. Forced refresh ignores freshness, never offline mode or cancellation. Snapshots are endpoint-scoped, and memory retains only the latest snapshot, including when persistence is unavailable.

OpenCode Free's experimental transport launches a locally installed Bun executable lazily for requests to `https://opencode.ai/inference/` only; it never downloads a runtime. `PI_OPENCODE_FREE_BUN` selects that executable. The child listens on loopback with a random per-process token, forwards only inference paths to the fixed HTTPS origin without following redirects, removes hop-by-hop headers, propagates cancellation, and streams responses. Startup has a ten-second deadline. Session shutdown disposes the child and temporary script; startup failures and child exits also clean up. Other origins and paths use the original fetch unchanged, and explicit caller fetch implementations retain precedence. The transport does not alter system prompts or record request bodies.
